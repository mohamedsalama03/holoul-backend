## Object integrity and access

`PrivateObjectStore` is owned by Documents, and its AWS SDK implementation stays in Documents/Adapters. The S3 client uses explicit credentials, a fixed HTTPS endpoint, certificate validation, finite timeouts, bounded retries and no redirects. There is no provider URL in API output. Local SeaweedFS exposes only private S3 to the internal network; master/filer/volume HTTP interfaces bind loopback, internal gRPC requires storage mTLS, and there are no host storage ports. Its runtime credential is bucket-scoped; bootstrap credentials and the encryption key are mounted only where needed.

Bootstrap enables bucket versioning, private bucket ACL, `BucketOwnerEnforced` ownership and default AES256 encryption. SeaweedFS 4.47 returns 501 for AWS `PutPublicAccessBlock`; that API is not claimed as supported. Equivalent private access is established by disabled public object grants, no anonymous identity, bucket-scoped runtime permissions and no runtime ACL/admin actions. Bootstrap probes verify unsigned listing and known exact-version GET are denied, and runtime bucket/object ACL mutations fail. A public-read header on PUT is ignored by this provider under enforced ownership: the probe verifies the resulting effective ACL has only its canonical owner's full control and unsigned GET still fails. Every synthetic probe version is deleted exactly.

Each normal PUT requests AES256 and includes the exact SHA-256, MIME and size. `If-None-Match: *` prevents replacement. A retry after a 412 is accepted only if metadata and the actual bytes of the existing immutable version match. Other ambiguous provider failures remain retryable. These semantics follow the [S3 PutObject API](https://docs.aws.amazon.com/AmazonS3/latest/API/API_PutObject.html).

The returned version ID must be nonempty and non-null. All downloads name that exact version. `openVerified()` checks returned identity and metadata, spools at most 10 MiB into a private temporary file, and verifies the full size and SHA-256 before returning a readable stream. The application reauthorizes before releasing bytes. `statVersion()` and bounded version listing support interrupted-upload recovery and orphan reconciliation; deletes always name a version. Cleanup grace periods, leases and retained-revision references remain domain responsibilities.

Storage-server and browser TLS certificates are separate. The local self-signed storage certificate has a storage DNS SAN and is explicitly trusted by the client. Only its public certificate is shared with application containers. Production requires operator-managed certificates, secrets, encrypted storage/backup facilities, retention and recovery procedures; local Compose does not prove those deployment controls.

## Malware processing

The actual ClamAV daemon has `network_mode: none`, a read-only root, no application credentials, one scan thread, 4 GiB memory, one CPU, 32 PIDs and a bounded 128 MiB private temporary filesystem. PHP sends bounded chunks through a Unix socket using the [documented INSTREAM protocol](https://docs.clamav.net/manual/Usage/ClamdProtocol.html). Responses are reduced to clean/infected/unavailable; filenames and signature diagnostics are not exposed or logged by the application. Unavailable, timed-out or stale-signature scanners cannot approve a document.

Before each scan the adapter checks the daemon's loaded signature timestamp, with a maximum age of 48 hours and at most five minutes of future clock skew. Separate FreshClam initialization/update services share only the signature database; they never receive document bytes, sockets, S3 credentials or database credentials. The scanner mounts signatures read-only and checks for updates every minute. Limits include 10 MiB input, 40 MiB aggregate scan expansion, 256 files, eight recursion levels and 15 seconds scan time. ClamAV reports exceeded limits/encryption as detections, which remain fail closed. Signature acquisition uses ClamAV's normal authenticated database verification; there is no custom bypass or artificial clean fixture database.

## Structural inspection

The inspector communicates only through a Unix socket. Its container has no network, no provider/database credentials, a read-only root, 512 MiB memory, one CPU, 32 PIDs and 128 MiB private tmpfs. Each inspection runs in a separate process group with a 20-second wall deadline, CPU limits of 15/16 seconds, 384 MiB address space, 60 MiB output, 32 file descriptors and no core dumps. The supervisor kills the whole process group and removes its temporary input. A caller has a single bounded exchange deadline. Worker output is limited to a finite result and reason code.

PDF inspection requires a PDF header at byte zero, a final EOF marker, no encryption, and a warning-free QPDF check. The [QPDF JSON object model](https://qpdf.readthedocs.io/en/stable/json.html) exposes actual objects, including those stored inside compressed object streams and escaped names. Every object and decoded stream is inspected; active actions, JavaScript, attachments, embedded files, external references, forms/XFA, multimedia and executable/archive payload signatures are rejected. Unsupported or undecodable stream filters fail closed. Limits include 500 pages, 10,000 objects, 40 MiB decoded streams, bounded traversal and explicit QPDF parser/filter limits. This is a restricted static PDF profile, not a renderer or a guarantee that arbitrary PDFs are safe in every viewer.

DOCX inspection requires a nonencrypted ZIP with consistent local/central records, no prefixes/gaps/trailing payloads, no ZIP64, duplicate names, traversal, symlinks, nested archives or executable parts. There are at most 256 entries, 8 MiB per expanded entry, 40 MiB aggregate expansion and a maximum 100:1 ratio; actual reads also enforce bounds and CRC checks. Every XML part is parsed with DTDs/entities/external entities/processing instructions forbidden and bounded depth/node counts. Required OOXML content types and the Word document relationship/root are verified. Macros, ActiveX, embedded objects, external relationships, templates, altChunk and executable field instructions are rejected. Only structurally checked PNG/JPEG embedded media are accepted; vector images, embedded fonts and other unsupported codecs are intentionally rejected. This strict profile can reject otherwise legitimate complex office documents.

Reasons are limited to `invalid_structure`, `dangerous_content`, `resource_limit`, `encrypted_document`, and `format_mismatch`. Unexpected infrastructure failures return unavailable so durable work can retry in quarantine. No raw parser diagnostics or document content enter normal logs.

A valid PDF/ZIP polyglot is rejected independently of QPDF validation. Its regression fixture is accepted by QPDF with exit zero and is simultaneously recognized as a ZIP; the inspector rejects the dual format before processing it.

## Required real-service checks

`tests/Feature/Documents/DocumentAdaptersTest.php` exercises real S3 immutable retries/version retrieval/checksum mismatch, real clean/EICAR ClamAV verdicts, the real isolated parser, and unavailable-service failures. `tests/Python/test_document_inspector.py` runs inside the pinned inspector runtime and covers compressed PDF object-stream JavaScript, encryption, active content, external DOCX relationships/entities/macros, renamed executables, nested archives, media/polyglots, expansion limits and malformed structures. These join the full application, concurrency, production HTTP and image/source security gates; they must not be replaced by mocks or skipped when services are unavailable.

The focused real-service pass completed with 6 PHP tests/48 assertions in 2.531 seconds and 10 Python tests against the built image's `/opt/holoul/inspect.py` in 14.869 seconds. Bootstrap's real permission/encryption probes passed. Initial failures exposed the unsupported PublicAccessBlock API, an insufficient four-volume local storage limit (raised to sixteen), an overstrict `.rels` suffix check, a minimal PDF fixture missing resources and the SDK returning XML long sizes as strings. They were corrected and rerun. Failed synthetic storage probes were removed by exact version. These focused results do not replace the final full production gate and vulnerability scans.
