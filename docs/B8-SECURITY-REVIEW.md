# B8 focused security and upgrade review

This review covers the new reporting/audit HTTP boundaries, owner aggregate queries, report snapshot consistency, bounded document metadata reads, exact B7 migration fixture, synthetic performance fixture/profiler, production configuration and operational telemetry. It is a focused code review with scoped PostgreSQL evidence, not an independent penetration test or final production certification.

## Findings addressed

1. **Inconsistent aggregate snapshots.** Multiple READ COMMITTED statements could previously observe different committed submissions in one report. Reporting now opens a REPEATABLE READ transaction before its first identity read, with bounded transaction retry. An independent PostgreSQL connection commits a submission between the count and subsequent aggregate statements; all returned sections keep the same snapshot.
2. **Document list N+1.** Per-attachment metadata and quarantined-scan eligibility reads increased with page size. The Documents-owned bulk contract checks exact parent/customer/customer-user ownership for the entire bounded set, locks records in ID order and performs one additional eligibility query only when needed. Existing visibility and current authorization remain in Projects/Application. Measured HTTP SELECT counts for 1/3/25 cleared documents changed from 16/18/40 to 16/16/16.
3. **Invalid year-zero dates.** PHP's calendar parser accepts a year that PostgreSQL timestamps reject. Report window validation explicitly rejects year `0000`, returning the validation envelope instead of reaching a database type error. A focused HTTP regression is included.
4. **Profiler transaction boundary.** The initial document profiling call omitted the authorized metadata transaction. The profiling script now reacquires current identity/parent context inside a transaction before reading document metadata. The wrapper creates and clears 25 real attachments before this profile runs.
5. **Vacuous upgrade evidence.** The exact B7 fixture now creates an AI decision receipt, a notification uncertain attempt followed by explicit operator replay and successful second generation, a notification preference change, and command receipts before migration. Those tables must be nonempty, remain unchanged after upgrade, and return the original receipt on exact replay afterward.
6. **Incomplete endpoint validation.** Production database TLS validation now requires a network hostname/IP, rejecting Unix-socket paths that cannot provide TLS. Storage requires an absolute HTTPS endpoint with a valid host and no userinfo, query or fragment. Origin/storage ports and production Redis/SMTP hosts and ports are validated; embedded transport URIs cannot substitute for the declared verified transport.
7. **Database connection-string delimiters.** Framework review confirmed that database name, port and CA path are interpolated into the PostgreSQL DSN. Validation now bounds database identifiers and numeric TCP ports and rejects delimiter/control characters in validated file paths. A regression creates an otherwise readable CA filename containing `;sslmode=disable` and verifies that configuration validation rejects it before connection construction. Username/password continue through their separate framework credential arguments.
8. **Secret-path canonicalization.** The original lexical workspace-prefix check missed traversal and external symlinks pointing into the workspace. Secret exclusion now compares resolved file/workspace paths. Tests use real readable temporary files and symlinks, reject direct/traversal/symlink access to workspace files, and retain support for an external symlink whose actual target also remains outside the workspace. This checks file placement; it does not certify a deployed secret manager or escrow policy.
9. **Testing startup exemption.** `APP_ENV=testing` alone no longer skips configuration validation. The exemption requires the explicit `local-verification` deployment profile; the separate local initialization exemption remains. A child-process regression proves that a production profile with testing mode rejects startup before executing the requested command, including the path used by workers that have no HTTP readiness gate.

## Boundaries reviewed

- Every report requires a current enabled authenticated staff identity, inherited staff MFA, verified email and the explicit permission. A customer with an erroneously granted reporting permission still fails the staff-kind check. Broad aggregates are intentionally authorized by `reporting.read`; they do not grant access to private resource text. Initial grants are Super Admin, Administrator and Project Manager. Audit investigation is separately restricted to Super Admin's `audit.investigate` grant.
- Authorization is performed inside the same reporting transaction. Existing identity/session locks serialize account changes; the supported staff-role mutation increments the identity authorization version and revokes sessions. A lock conflict/serialization failure retries the outer transaction with a new snapshot, at most twice. Permission is rechecked on every request, including later audit pages. The review does not treat direct migration-owner SQL modifications as a supported authorization mutation path.
- Reporting imports only owner read contracts, adds no business writes, and selects aggregate numeric/state/date fields plus taxonomy IDs. The reviewed Proposals→Intake join reads request IDs/submission dates for proposal timing only. Customer PII, descriptions, document bodies and AI content are absent. Budget and accepted proposal value remain separate, separately grouped by currency, and never represented as revenue.
- HTTP filter names are allowlisted. Date ranges are paired, ordered, UTC, no later than today and at most 366 days. Category combinations are bounded; malformed UUIDs fail validation. Audit pages default to 25 and cap at 100, using authenticated opaque seek cursors bound to filters and date range. Stable timestamp/ID ordering preserves ties. Cursor reuse with changed filters and tampering fail validation.
- Audit responses select identifiers, event/subject codes and timestamps only, excluding audit metadata and joins to identities or business text. Every investigation appends its own safe event. Existing append-only SQL restrictions remain intact. No export or raw SQL interface is introduced.
- Reports have private/no-store responses, a 60/minute actor limit and a five-second timeout **per SQL statement**. Date/output bounds and fixed query count do not imply fixed execution time as data grows; production plans, statement timeouts and resource use still require operational monitoring.
- Bulk document metadata requires the caller's authorized transaction, at most 100 distinct IDs, and a match for every requested owner tuple. It fails the entire request on any mismatch. It returns the same bounded DTO fields as individual metadata and never object keys/versions. Projects retains customer/internal visibility and excludes unfinished customer uploads.
- Configuration validation emits only stable failure codes, never configured hosts, file paths or secret contents. Real production cannot inherit the local synthetic profile's exemptions. Network/CA/secret assertions complement deployment verification; they cannot prove firewall rules, certificate renewal, bucket encryption/version policy, secret-store access or production provider approval. Optional AI/provider availability remains separate from core readiness.

## Evidence limits and launch decisions

The synthetic performance fixture is explicitly gated to the local verification deployment, localhost, runtime database identity, sandbox SMTP and production image without PHPUnit. Synthetic credentials stay in a private temporary manifest and identities/sessions/grants are disabled during cleanup; immutable history is retained. Profile exports omit SQL text, bindings and source content. CLI owner-query timings exclude HTTP authentication and networking; HTTP load is measured separately. A requested page limit does not claim that many rows were returned: the current proposal fixture has one accepted proposal per request, and the document fixture has 25 attachments even at limit 100.

No new cross-owner or private-content escape was found in this reviewed B8 surface. Production commissioning remains a separate gate: real secrets/TLS/providers, approved retention/privacy and AI terms/budget, off-host backup destination and recovery objectives, alert routing, and accepted single-host risks must have owners and evidence. Local sandbox/provider/restore/load results alone cannot close those decisions. Database-owner access can still alter database-only audit history; independent archive policy remains an operational responsibility.

The launch classification remains **NOT PRODUCTION READY — BLOCKERS REMAIN**. See [the launch checklist](B8-LAUNCH-CHECKLIST.md): final-gate evidence is complete with a strict burst failure, and mandatory production commissioning decisions remain open.
