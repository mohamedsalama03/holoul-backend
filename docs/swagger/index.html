Before you integrateSessions, CSRF & request conventions

Browser authentication

  1. Use the application’s HTTPS origin. Initialize CSRF at GET /sanctum/csrf-cookie when the flow requires a session.
  2. Sign in at POST /api/v1/auth/login. Staff must complete the returned MFA step before protected APIs are available.
  3. The browser manages the HttpOnly session cookie. URL-decode XSRF-TOKEN into X-XSRF-TOKEN where required; re-read it after session rotation.

Follow each operation

Security, CSRF requirements, permissions, validation, idempotency and concurrency headers are documented per operation. Public guest intake does not imply session initialization.

For customer directory pagination, keep the filters and sort unchanged while following meta.next_after. Omitted sort preserves oldest-first behavior.

Portable reference
