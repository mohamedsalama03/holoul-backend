# B8 baseline and scope

B7 was approved at `96445baded70ddd2e4d8b8617793c78a4a3e1816`, parent
`bf738302657f8da1bca911058186a24e87b7ea37`. The working tree was clean before B8.
The baseline contains 27 migrations, 50 permissions and 155 routes. Its final
gate passed 746 Unit/Feature tests (7,081 assertions), 9 architecture tests
(34,876 assertions), and 17 document inspector Python tests.

B8 is limited to operations, staff reporting, audit investigation, measured
performance and capacity, production configuration, backup/restore validation,
deployment/recovery and final security/regression evidence. The approved B0
module ownership, immutable history, durable PostgreSQL intent, private object
versions, separate database identities and B1–B7 security boundaries remain.

The local verification host reports eight Docker CPUs and 8,176,410,624 bytes of
Docker memory. Its private Compose stack is synthetic. Local HTTPS certificates,
SMTP capture, backup files and sandbox AI are not evidence of a commissioned
production deployment. External AI remains disabled unless its separate policy
and budget approval gate is completed. No frontend or further domain is authorized.

The final verification report records measured results, the exact release and
image identities, a launch checklist and every unresolved mandatory blocker.
No production-ready assertion is made from a local gate alone.

The user supplied the intended launch envelope during B8: an Ubuntu VPS with
2 CPUs, 8 GB RAM and 1 TB disk, approximately 150 customers, 100 projects and
20 concurrent users. The load harness constrains all application/dependency
containers to the same two logical CPUs. Actual VPS disk/network performance,
domain/TLS, secrets, private-service policies and operational approvals still
require target-environment evidence.
