# دليل ربط PublicPortfolio وContact

العقد: OpenAPI 3.1.1، `1.4.0-public-services-candidate`، 202 عملية. الأصل المحلي للربط هو `https://localhost:8443`، والمسارات نسبية إلى الأصل نفسه. حزمة Swagger مرجع مستقل للقراءة، وليست خادم API ولا تستخدم المنفذ 8876 للتطبيق.

## الاعتماد والتوافق

نسخة OpenAPI المرجعية في Backend هي `docs/openapi.json`. البصمة: `7739bd957665b285c3baea8a4883aa987d6d11dee3fb43bcc5ef1ff9fb0c8051`. قارنها قبل نقل نسخة العقد إلى كل واجهة في commit مستقل يملكه فريقها. لم تُعدّل نسخ العقود أو شفرة Website/Dashboard ضمن هذه الدفعة. العمليات الـ182 والمكونات القديمة لم تتغير؛ سجل الإضافات العشرين في CHANGELOG.md.

## قراءة المعرض

استعمل عمليات `publicPortfolioList` و`publicPortfolioDetail` و`publicPortfolioCategories` و`publicPortfolioImage`. لا تستدعِ CSRF bootstrap لعرض المعرض وحده، ولا تعتمد على هوية المستخدم لتحديد المحتوى العام. لا تصدر هذه القراءات Set-Cookie.

ترقيم القائمة بـcursor مرتبط بالفلتر، والحد الافتراضي 12 والأقصى 48. صَنّف باستخدام `web/mobile/business/commerce/custom`، وهي رموز مستقلة عن تصنيفات تقديم الأفكار ذات معرفات UUID. استخدم `meta.next_cursor` كما هو، وأزل التكرار حسب id عند تحديث القوائم المتغيرة. النصوص بيانات عادية؛ لا تُعرض عبر HTML غير موثوق.

معرف المشروع الجديد UUIDv7، ويحافظ الاستيراد المعتمد لاحقًا على UUIDv4 العام للمشروع القديم. معرف الصورة العامة يخص نسخة النشر ويختلف عن معرف أصل الرفع الإداري. لكل نشر معرفات صور عامة جديدة؛ الروابط القديمة لا تعود بعد سحب النشر أو إعادة النشر. استخدم URL النسخة المعادة في العقد دون تخمين مفتاح تخزين أو جلب الأصل الخام.

النجاح العام: `public, max-age=0, s-maxage=60, must-revalidate`. الأخطاء والكتابات no-store. لا تضف stale-while-revalidate أو stale-if-error أو مدة مستقلة في Next.js/HTML/image proxy. لا يوجد shared cache في Nginx المحلي الحالي. قبل قبول التكامل يجب قياس نافذة السحب الكلية عبر أصل الموقع والمتصفح وأي وسيط/CDN؛ لا يكفي اختبار Laravel أو نجاح المنفذ 8443 وحده. اختبر نشر A ثم B وسحب B وإعادة نشر C، وجميع روابط A/B والقائمة والتفاصيل والعدادات والصور، مع تعطل origin أيضًا. الميزانية 60 ثانية إجمالًا وليست لكل طبقة.

## إرسال التواصل

ابدأ صراحة بـ`GET /sanctum/csrf-cookie` عند دخول سير الإرسال، ثم POST `/api/v1/public/contact-messages` مع credentials من الأصل نفسه وOrigin وX-XSRF-TOKEN الحالي وIdempotency-Key UUID عشوائي. endpoint يقبل الضيف والعميل والموظف، لكنه لا ينشئ حسابًا ولا يغيّر الجلسة أو persona ولا يصدر كوكي جلسة بديلة. عند login/MFA استخدم CSRF الجديد؛ لا تعاود إرسال قيمة قديمة.

حوّل حقل الواجهة `name` إلى `full_name`، واجمع اختيار البلد والهاتف في هاتف دولي صريح يبدأ +. أرسل فقط `full_name,email,phone,company,message` وفق الحدود في OpenAPI؛ لا ترسل country أو رمز العلم أو user_id أو عنوان المستلم. لا تدعم العملية مرفقات. يعاد الرد 201 بعد حفظ الرسالة والإيصال ونية الإشعار في معاملة واحدة؛ هذا يؤكد الاستلام ولا يؤكد وصول البريد.

احتفظ بالمفتاح وبالجسم المطبع لنفس محاولة المستخدم. داخل نافذة 72 ساعة من أول حفظ، التكرار المطابق يعيد الإيصال نفسه، حتى بعد تغيير حالة الرسالة أو تنقيحها؛ جسم مختلف بالمفتاح نفسه يعيد 409. الحد الزمني نصف مفتوح: عند أول حفظ +72h يبدأ المفتاح عملية جديدة. لا تولّد مفتاحًا جديدًا تلقائيًا عند نتيجة مجهولة أو انتهاء النافذة؛ اجعل إعادة الإرسال المقصودة قرارًا للمستخدم. راعِ 429 وRetry-After و503، ولا تخفّض حماية المعدل لتجاوز الاختبارات.

## إدارة الوحدتين

اقرأ `GET /api/v1/admin/public-content/capabilities` بعد اكتمال جلسة الموظف وMFA. الصلاحيات الست boolean مستقلة عن Identity/Staff capabilities القديمة؛ لا تضف قيمًا إلى enums القديمة ولا تستنتج صلاحية من اسم الدور في الواجهة. المنح الحالية لهذه الوحدتين محصورة في Super Admin وAdministrator. سياسة الدعوات ومنح أدوار الموظفين بقيت كما هي.

احتفظ بـetag الحالي الوارد في المورد وأرسله في If-Match عند التعديل. 412 يعني قراءة النسخة الجديدة ومراجعة التعارض؛ لا تكتب فوقها تلقائيًا. النشر والسحب وحذف الصورة الحساس وتنقيح الرسالة تتطلب تأكيد كلمة مرور حديثًا عبر آلية Identity الحالية إضافة إلى التفويض على العملية. إرسال If-Match قديم لنشر بنفس مفتاح الإعادة المطابق يعيد النتيجة المحفوظة وفق العقد، مع إعادة فحص الصلاحية الحالية.

الرفع الإداري: احجز صورة بالحجم وSHA-256 والنوع الفعلي، ثم PUT بايتات خام إلى content، ثم اقرأ الحالة حتى ready أو rejected/expired/removed. الحدود: JPEG/PNG/WebP ثابت، 5 MiB، 24 مليون بكسل، 8 صور للمشروع. لا تنشر قبل ready لجميع الصور المطلوبة واختيار الغلاف والصورة المميزة واعتماد حقوق النشر. المعالجة تعيد WebP منزوع metadata دون تكبير؛ إخفاق الصورة يظهر كـfailure_code ولا يتحول إلى نشر تلقائي.

## صندوق التواصل والإشعارات

واجهة Dashboard المقترحة للقراءة المخوّلة: `/admin/contact-messages/{message}`. هذه صفحة مطلوب أن ينفذها ويعتمدها فريق Dashboard؛ لم تُنشأ هنا. API الإدارة موجود في `/api/v1/admin/contact-messages/{message}` ويظل مخوّلًا. لا تُضف قراءة عامة بديلة للرسائل ولا تجعل معرفة رقم الإيصال سلطة وصول.

المستلم `info@holoul.ly` لا ينشئ مستخدمًا ولا يمنحه صلاحيات. الإشعار المحلي عبر Mailpit مرجعي فقط، دون نص الرسالة أو بيانات المرسل أو رابط صفحة غير مقبولة. تفعيل روابط البريد الحقيقي محكوم بقبول صفحة Dashboard وتمكين إرسال الإنتاج صراحةً. delivery_status قد يكون pending/sending/sent/uncertain/blocked/suppressed؛ اقرأ القيم المعرّفة في المخطط. uncertain لا يعاد إرساله آليًا. لا تعرض أن العميل استلم ردًا لأن الإشعار الإداري أُرسل.

التنقيح اليدوي المخوّل يحذف محتوى الرسالة وبيانات الاتصال من المصدر التشغيلي ويحفظ الإيصال والتاريخ؛ لا يمحو نسخًا احتياطية قديمة. مدة 180 يومًا معلّقة والحذف/التنقيح الآلي معطل. راجع CONTACT-RESTORE-PROCEDURE.md قبل أي استعادة.

## بيانات الربط والتحويل

الأمثلة في response-examples.json ردود فعلية ببيانات اصطناعية، وتشمل مسودة ومنشورًا وصورة مرفوضة وإيصالًا وتكراره. روابط أمثلة النشر تاريخية وسُحبت عمدًا في الاختبار؛ ليست محتوى عامًا دائمًا. جهّز بيانات تكامل جديدة عبر العمليات المخوّلة. بيانات الدخول الاصطناعية تبقى في ملف الاختبارات الخاص ولا تدخل الحزمة أو العقد.

قائمة تقديم الأفكار المعتمدة 12 رئيسيًا و49 فرعيًا لا تعني أن كل البيانات التجريبية اختفت. بيانات B8 تبقى دون تعطيل حتى قبول خطة التحويل الصريحة. لا يُحوّل المخزن القديم للمعرض أو مستخدموه تلقائيًا؛ راجع TAXONOMY-AND-LEGACY-CUTOVER-AR.md. اختبار الموقع ولوحة الإدارة بعد ربط الوحدتين وقياس VPS والتعافي خطوات قبول لاحقة؛ النجاح المحلي ليس اعتماد إنتاج.
